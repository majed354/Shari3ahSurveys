# تقييم الطلاب لكل مقرر وشطر: عقد البيانات v2

رابط JSON الخام المباشر القابل للاستهلاك:

[student-course-evaluations.json](https://raw.githubusercontent.com/majed354/Shari3ahSurveys/main/data/course-evaluations/v2/student-course-evaluations.json)

الإصدار `course-student-evaluations-v2` مستقل عن `data/course-evaluations/1447/course-item-scores.json` وعن ملفات JavaScript الحالية. لا يغير عقد أي مستهلك قديم. JSON واحد يضم السنوات 1445 و1446 و1447، والفصول 451 و452 و461 و462 و471 و472. لم يُعدّل مشروع أتمتة التقارير.

## المصدر وإعادة البناء

المصدر الأصلي المحلي:

```text
أكواد تقييم الطلاب/استطلاعات الطلاب حول كافة المقررات في برامج كلية الشريعة 1445-1447.xlsx
```

المصنف وأكواد مطابقة المحاضرين لا تُرفع إلى المستودع. التحويل يعتمد فقط على المصنف المحدد، ولا يحتاج إلى ملفات أعضاء هيئة التدريس أو مشروع أتمتة التقارير. بيانات JSON المنشورة مجمعة على مستوى المقرر والشطر.

من جذر المستودع، باستخدام Python 3.10 أو أحدث دون تبعيات إضافية:

```bash
python3 scripts/build_student_course_evaluations.py
python3 scripts/build_student_course_evaluations.py --source "/path/to/original.xlsx"
python3 scripts/build_student_course_evaluations.py --check
python3 -m unittest discover -s tests -v
```

يدعم `--output` تحديد وجهة أخرى. `--check` يتحقق من التطابق الحرفي بين إعادة البناء وJSON المحفوظ دون الكتابة. الإخراج حتمي بلا تاريخ إنشاء متغير، ويُستبدل الملف بعد اكتمال التحقق فقط. يتوقف التحويل عند تغير رؤوس الأعمدة أو هوية البرنامج أو ظهور مقر أو نموذج استطلاع غير مسجل أو عدد إجابات غير صحيح. يُقرأ اسم السنة من الورقة وعلاقتها داخل XLSX، ولا يُفترض ترتيب الأوراق.

## الهوية والخصوصية

- الشطر من **المقر فقط**: `حوية → male`، و`حوية طالبات → female`.
- هوية البرنامج من **الدرجة العلمية والتخصص**، مع التحقق من القسم الأصلي. معرفات `programId` توافق المعرفات الحالية في المستودع. مثلًا `p04` بكالوريوس القرآن وعلومه، و`p02` بكالوريوس الدراسات الإسلامية، و`p10` ماجستير الدراسات القرآنية المعاصرة.
- هوية السجل: السنة، الفصل، البرنامج، اسم المقرر الأصلي. تبقى المسميات المتشابهة إملائيًا منفصلة. لا تُدمج مقررات بين البرامج اعتمادًا على تشابه الاسم.
- المصدر لا يحتوي عمود رمز مقرر؛ `courseCode` دائمًا `null` و`courseCodeStatus = not_in_source`. لا تُستخدم قائمة مقررات خارجية ولا مطابقة من برنامج آخر.
- يُحفظ نص البنود مع تسوية المسافات وUnicode NFC فقط، دون إعادة صياغة أو تصنيف معرفي/مهاري/قيمي.
- لا يُنشر اسم المحاضر أو رقمه أو معرف مشتق من هويته أو تقييمه الفردي. تستخدم هويته داخليًا لكشف السجلات المتداخلة فقط. يتحقق التحويل أيضًا من عدم تسرب أسماء المصدر إلى قيم النصوص المنشورة.

## الحقول العليا

| الحقل | الوصف |
|---|---|
| `schemaVersion` | `course-student-evaluations-v2`؛ أي تغيير كاسر لاحق يحتاج مسارًا أو إصدارًا جديدًا |
| `source` | اسم المصنف، بصمة SHA-256، الحجم بالبايت، أسماء الأوراق وصيغة المصدر |
| `scale` | درجات الإجابة وتسمياتها؛ ترتيب الأعداد في كل توزيع يطابق هذا الترتيب |
| `programs` | دليل البرامج: `id`، `degree`، `specialty`، `sourceDepartment` |
| `itemDefinitions` | قاموس البنود بالمفتاح `itemId`؛ يحتفظ بالسنة والفصل والنموذج والموضوع ورقم البند ونصه |
| `methodology` | قواعد الهوية والفصل والتجميع والتكرار والبيانات الناقصة والخصوصية |
| `quality` | الحصر والمطابقة لكل سنة/فصل/برنامج/شطر، والحالات المستبعدة وأسبابها |
| `records` | سجل واحد لكل سنة وفصل وبرنامج ومقرر؛ يتضمن الشطرين والإجمالي |

ترتيب `responseCounts` هو `[غير موافق بشدة، غير موافق، محايد، موافق، موافق بشدة]` بأوزان `[1,2,3,4,5]`.

## سجل المقرر

| الحقل | الوصف |
|---|---|
| `id` | معرف حتمي لهوية السجل العامة، لا يتضمن هوية محاضر |
| `academicYear` | السنة الهجرية نصًا، مثل `1447` |
| `semester` / `semesterNumber` | رمز الفصل الأصلي مثل `471` / ترتيبه مثل `1` |
| `programId` | رابط إلى دليل البرامج؛ لا يكفي اسم المقرر وحده للاختيار |
| `courseName` | اسم المقرر من المصدر |
| `courseCode` / `courseCodeStatus` | `null` / `not_in_source` |
| `sourceSheet` | اسم ورقة المصدر |
| `colleges` / `courseTypes` | قيم الكلية وأنواع المقرر الأصلية الداخلة في التجميع |
| `cohorts.male` | بيانات الطلاب، أو `null` عند غيابهم من المصدر |
| `cohorts.female` | بيانات الطالبات، أو `null` عند غيابهن من المصدر |
| `cohorts.total` | الإجمالي المحسوب من بيانات الشطرين المتاحة، مع وصف تغطيته |

لا توجد سجلات فصل `all` لتجنب العد المزدوج مع الفصول الأصلية. إن احتاج المستهلك تجميعًا سنويًا، يجمع توزيعات البند نفسه في الفصول المختارة أولًا، مع مراعاة تغير نموذج الاستطلاع والبنود.

## بيانات الشطر والبند

| الحقل | الوصف |
|---|---|
| `sectionCount` | عدد هويات الشعب المميزة بحسب المقر ونوع المقرر ورقم الشعبة ضمن المقرر والفصل |
| `sectionEvaluationCount` | عدد هويات تقييم الشعب من المصدر، بما فيها الحالات المعزولة؛ قد يشترك أكثر من محاضر في رقم الشعبة نفسه |
| `quarantinedEvaluationCount` | عدد هويات التقييم التي عُزلت بسبب تعارض التكرار |
| `respondents` | دائمًا `null`؛ المصدر لا يتيح معرفة عدد الطلاب الفريدين |
| `respondentCountStatus` | `unique_students_not_identifiable` |
| `items` | توزيعات البنود المجَمعة؛ يُقرأ نص كل بند من `itemDefinitions[itemId]` |
| `allItemResponseSummary` | ملخص موزون بكل إجابات البنود المتاحة؛ ليس قياس مجال تعلم أو متوسط بند الرضا العام |

حقول كل عنصر في `items`:

| الحقل | الوصف |
|---|---|
| `itemId` | رابط إلى تعريف البند: `academicYear`، `semester`، `instrument`، `topic`، `number`، `statement` |
| `statementSource` | `source_rows` لنص موجود في الصفوف؛ `missing_in_source` لنص مفقود؛ `period_template` لبند غاب كاملًا عن التقييم واستُخدم تعريف النموذج لإظهار الفجوة |
| `status` | `complete` أو `no_responses` أو `partial` |
| `responseCounts` | الأعداد الخمسة بعد جمع تقييمات الشعب؛ `null` عند نقص/التباس أي مساهمة لازمة |
| `responses` | مجموع الأعداد **لبند واحد**، وليس عدد الطلاب الفريدين؛ `null` للنتيجة الجزئية |
| `scoreNumerator` | مجموع الدرجة × عدد الإجابات؛ عدد صحيح قبل القسمة |
| `mean` | `scoreNumerator / responses` مقربًا إلى 6 منازل؛ `null` عند عدم وجود إجابات أو نقص/التباس البيانات |
| `knownResponseCounts` | موجود فقط مع `partial`؛ يجمع الأعداد المقبولة المعروفة لأغراض التتبع، ولا يحولها إلى نتيجة مكتملة |
| `missingReasons` | موجود مع `partial`؛ أسباب عدم اكتمال النتيجة |
| `sourceRows` / `acceptedRows` | عدد صفوف المصدر لهذا البند / عدد الصفوف المقبولة بعد المعالجة |
| `contributingEvaluations` | عدد تقييمات الشعب المقبولة ذات الأعداد الخمسة المكتملة لهذا البند |

`allItemResponseSummary` يستخدم حقول الحساب والحالة نفسها، لكن أعداد إجاباته تمتد عبر **جميع البنود**؛ يجب ألا تستخدم كعدد طلاب. لا تُنشأ درجات معرفية أو مهارية أو قيمية داخل هذا الملف. تصنيف البنود في الخريطة المستقلة [`item-classification.json`](../data/course-evaluations/item-classification.json) بحسب معنى البند، ودرجات الفئات في [`course-domain-scores.json`](../data/course-evaluations/course-domain-scores.json). يقرأ الموقع وأتمتة النواتج الخريطة نفسها؛ انظر [تصنيف البنود](item-classification.md).

`instrument` يميز نموذج المصدر `legacy` عن `electronic_learning`. في الفصل 452 يوجد النموذجان؛ لا يُعامل غياب أحدهما عن شعبة تستخدم الآخر كنقص بنود. يُتحقق من اكتمال مجموعة البنود داخل النموذج أو النماذج الموجودة في تقييم الشعبة. التعريفات المختلفة تظل منفصلة.

عند `statementSource = missing_in_source` يجب أن يبقى نص البند مفقودًا لدى المستهلك حتى إن وجد نصًا للبند نفسه في تعريف الفترة مأخوذًا من صفوف أخرى. عند `period_template` توجد هوية ونص للنموذج، لكن إجابات هذا التقييم مفقودة.

## حساب الإجمالي ومعالجة الاستثناءات

لكل بند، تُجمع أعداد الإجابات الخمس لكل مقرر وشطر عبر تقييمات الشعب المقبولة **قبل** حساب المتوسط. ثم يُعاد الحساب بعد جمع توزيعي الطلاب والطالبات. لا تُستخدم المتوسطات المقربة للشعب أو متوسط بسيط للشطرين.

يضيف `cohorts.total`:

- `source = sum_of_available_cohort_item_counts`.
- `includedCohorts` و`missingCohorts` لبيان الشطر الموجود والمفقود.
- `coverage = both_cohorts` إذا وجد الشطران، أو `available_cohort_only` إذا وجد أحدهما فقط.
- كل بند إجمالي له `includedCohorts` مستقل، لأن نماذج البنود قد تختلف بين الشطرين.

الإجمالي ذو شطر واحد هو **الإجمالي المتاح في المصدر**. لا يثبت وجود تقييم للشطر الغائب، ولا تُنسخ قيمته إلى الشطر الغائب. على المستهلك الذي يحتاج قياس الشطرين معًا اشتراط التغطية المناسبة على مستوى السجل والبند.

قواعد الاستثناءات:

1. التكرار المتطابق يُحذف فقط عندما لا تتعارض أي عبارة في هوية تقييم الشعبة نفسها.
2. إذا اختلفت أعداد أو نص بند مكرر، تُعزل **كل صفوف هوية التقييم المتداخلة**، بما فيها البنود التي اتفقت مصادفة؛ لا يُختَر تقرير عشوائي ولا تُجمع النسختان. نتائج البنود المتأثرة تصبح `partial` وقيمها الأساسية `null`، مع حفظ الأعداد الأخرى المقبولة في `knownResponseCounts`.
3. عدد إجابات خلية مفقود يبقى مفقودًا، ولا يتحول إلى صفر. الصفر الصريح يبقى صفرًا.
4. غياب بند داخل نموذج تقييم مستخدم يجعل ذلك البند جزئيًا. المجموعة المتوقعة للبنود مأخوذة من هويات البنود في المصدر لنفس الفترة والنموذج.
5. صف بلا اسم مقرر يُحصر في `unassignedRows` و`unassignedCounts`، مع رقم صف المصدر وسبب الاستبعاد؛ لا يُخمن له مقرر.

## مثال للاستهلاك

```python
import json
from urllib.request import urlopen

url = "https://raw.githubusercontent.com/majed354/Shari3ahSurveys/main/data/course-evaluations/v2/student-course-evaluations.json"
data = json.load(urlopen(url))
assert data["schemaVersion"] == "course-student-evaluations-v2"
record = next(r for r in data["records"] if
    (r["academicYear"], r["semester"], r["programId"], r["courseName"])
    == ("1447", "471", "p04", "تلاوة وحفظ (6)"))
for gender in ("male", "female", "total"):
    cohort = record["cohorts"][gender]
    if cohort is None:
        continue  # يبقى هذا الشطر مفقودًا
    for item in cohort["items"]:
        definition = data["itemDefinitions"][item["itemId"]]
        statement = None if item["statementSource"] == "missing_in_source" else definition["statement"]
        # استخدم نص البند وتوزيعه وفق قواعد المجالات لدى الأتمتة.
        # item["mean"] وresponseCounts يبقيان null إذا كانت البيانات جزئية.
```

نتيجة البند الأول «تم عرض خطة المقرر بالتفصيل في بداية الفصل الدراسي.» لتلاوة وحفظ (6)، البرنامج `p04`، الفصل 471:

```json
{
  "male": {"responseCounts": [0,0,1,0,2], "responses": 3, "scoreNumerator": 13, "mean": 4.333333},
  "female": {"responseCounts": [0,1,3,9,2], "responses": 15, "scoreNumerator": 57, "mean": 3.8},
  "total": {"responseCounts": [0,1,4,9,4], "responses": 18, "scoreNumerator": 70, "mean": 3.888889}
}
```

المثال مقتطف من حقول البند بعد فك مرجع `itemId`. المتوسط الإجمالي `70 / 18`، لا متوسط `4.333333` و`3.8` البسيط.

## نتائج التحقق

تم التحقق في 1 أكتوبر 2026 من المصنف ذي البصمة:

```text
d541d20f4ed48d822534bfa161981a4969ca9590863a61ebf05cb3e0e1ba40c7
```

- 321,575 صفًا من المصدر، و3,322 سجل سنة/فصل/برنامج/مقرر؛ معرفات السجلات فريدة.
- 15 برنامجًا بهويات توافق المستهلكين الحاليين؛ 168 تعريف بند بحسب الفترة والنموذج.
- 320,624 صفًا مقبولًا، و936 صفًا معزولًا ضمن 19 هوية تقييم متعارضة، و15 صفًا بلا اسم مقرر.
- 456 صف بند مكرر بالهوية في المصدر؛ عُزلت التقارير المتداخلة كاملة بسبب التعارض. لا توجد صفوف تكرار متطابق أُزيلت منفردة في هذه النسخة.
- 3 هويات تقييم ذات بنود ناقصة داخل النموذج؛ 520 بندًا جزئيًا في بيانات الشطرين، وتظل القيم الأساسية لها `null`.
